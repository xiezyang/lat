# FLD 清零加载验证（2026-11-28）

本次修改在 `6600-test` 上完成，继续使用固定 master 基线
`cf79c04a85bd8259892f5e24eb8762ae2d9cdc5b`。没有更新 master。

## 规则和修改

- `fld.s`：低 32 位取内存原始值，[127:32] 清零，[255:128] 保留。
- `fld.d`：低 64 位取内存原始值，[127:64] 清零，[255:128] 保留。
- 修正此前把上述清零、保留范围写反的说明和本地直接指令测试预期。
- LAT 的 `LATX_FLD_CLEAR` 默认 0，命令行 `-latx-fld-clear 0|1`，也可使用配置文件。
  开启后仅把 legacy MOVSS/MOVSD 内存加载改为直接向目标发射 `fld.s/d`。
  原有寄存器形式、存储形式和 VEX 翻译保留；关闭后使用原来的翻译选择。
- QEMU 增加独立 CPU 属性 `fld-clear=on|off`，默认 off；仅改变 `fld.s/d`。
  成功访存后才写目标和清零，沿用现有可选 x87 栈映射，保持高 128 位。
  不改变 `bt-6600`、`fldx.s/d`、其他浮点指令或 LSX/LASX 加载的规则。
- QEMU 源码不在本 LAT 仓库中；对应修改及直接指令测试完整保存为
  [6600-fld-clear-qemu.patch](6600-fld-clear-qemu.patch)，可应用到已有 6600 模型源码。

## 构建和配置

LoongArch 本机顺序构建 x86_64、i386 两个 LAT，使用已有构建配置：
`--enable-latx --enable-latx-avx-opt --enable-latx-flag-reduction --optimize-O1`
及已有测试配置。QEMU 在 x86_64 上重新构建，运行顺序为 QEMU → LAT → x86 客体。
所有 LAT 执行均显式设置 `LATX_SOFTFPU=0`、`LATX_SOFTFPU_FAST=0`，并通过命令行
再次指定；FLOAT80、STACK、128CAL、HASH、X86ADDI、KZT、MT 均关闭。
单独开启 FLD 时 `bt-6600=off`、LSX_AUTO_CLEAR=0；组合测试时
`bt-6600=on`、LSX_AUTO_CLEAR=1。未把地址转换选项作为浮点配置。

## 验证结果

| 检查 | 结果 |
| --- | --- |
| 修改前 QEMU 的直接加载 | 按新规则检查失败：单精度高 32 位全 1，XMM 高 64 位保留 |
| 最终 QEMU 的直接加载 | fld-clear 开/关分别与 bt-6600 开/关组合，4 组均通过，每组 24,578 次完整 256 位比较 |
| 原始直接 fld 用例修正后 | 32,768 次加载、131,072 次检查通过 |
| 原生 x86 参考 | x86_64、i386 两份自检程序均通过 |
| QEMU → LAT 新路径 | 两种客体分别在仅开启 FLD、组合开启 FLD/LSX 两种配置通过 |
| 关闭 LAT 开关 | 两种客体分别在 QEMU 新旧加载规则下通过 |
| 命令行覆盖环境 | 环境开、命令行关，两种客体均通过 |
| 不匹配模型反向检查 | QEMU 关闭新规则而 LAT 强开，两种客体均按预期报错、退出 1 |
| AOT 设置独立 | GDB 在 cpu_loop 入口核对两种客体的默认值和 FLD/AOT 的 4 种组合，共 10 组；SOFTFPU、FAST 实际值均为 0 |
| AOT 实际生成和加载 | 两种客体均通过 JIT、冷生成、热加载；测试运行器检查了热加载标记和对应客体路径 |
| 选项错误值 | 两种客体对环境和命令行的 2、-1、true、01 共 16 次输入均明确拒绝 |
| 受影响的既有向量回归 | 开启新 FLD/LSX 模型和 LAT 对应选项，26 个客体全部通过 |
| lat-pr-fast | 59 项全部通过 |
| QEMU 补丁格式检查 | 0 错误、0 警告（不要求补丁邮件签名） |

直接指令回归覆盖全部 32 个目的寄存器、4 组完整寄存器预置、16 个原始位模式、
4 种地址、连续 s→d→s、页末 4/8 字节加载及访存异常不改写目标。
原始位模式包括正负零、无穷、两类 NaN、次正规数和普通数据。

新增 `tests/integration/fld-clear.asm` 覆盖两种客体、多个目标寄存器、
MOVSS/MOVSD 内存与寄存器形式、VMOVSS/VMOVSD 内存形式、完整 YMM 状态和页末加载。
对应 `test-fld-clear-*` 已注册到 `latx-integration`；须使用匹配模型并设置
`LATX_FLD_CLEAR=1` 才运行。实际 AOT 验证使用同一测试运行器及其缓存加载检查。

既有 26 个客体包括九组向量操作，以及 LSX 自动清零、YMM 高位保存、条件保存、
VZEROALL、VMOVD、SSE4.1 等回归。该结果不代替完整 SPEC 或所有 x86 指令测试。

## 限制

本次验证为 QEMU 模型和 LAT 组合的功能正确性，未测真实 6600 硬件，未重跑 SPEC，
没有应用性能数据。实际 AOT 验证只覆盖本次定向客体，不代表所有 AOT 应用通过。
原有 AOT 缓存不会因切换 FLD 开关而重写，应使用各自独立、与目标行为匹配的缓存。
